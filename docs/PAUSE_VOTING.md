# Pause voting

Each open match room has a management-configured pause vote threshold from 1 to 10, defaulting to 1. A signed-in participant with server access may vote once while the loaded match is live and the server advertises pause control. The threshold counts rostered players, not connected clients. When reached, the server queues the existing fenced MatchZy pause request; the match remains live in snapshots until the agent reports its observed state. Players can resume using the existing control once the server advertises it. Administrators retain direct pause and resume controls.

Votes clear when a pause is requested, the observed phase or active setup changes, or management changes the threshold. A threshold larger than the roster cannot be reached; management can lower it or directly pause. A failed pause requires a new vote. The feature does not provide in-game voting or verify real CS2 operation.

The management and player views must render `PauseVoting` from `web/src/PauseVoting.tsx`. Supply `pauseVoteThreshold`, `pauseVotes`, and the snapshot's `controlRevision`; for players also supply `myPauseVote` and `actions.pause`. Replace the existing player pause button with the component's vote button and use the existing player control request (`POST /api/player/matches/{id}/control`, action `pause`). For management, supply `canConfigurePauseVoting` as `canConfigure` and call `PATCH /api/matches/{id}/pause-voting` with `{ "threshold": number, "revision": controlRevision }`. Refresh through the existing canonical live snapshot; do not update vote counts or lifecycle locally. The direct management pause button remains available. Disable both operations when the live connection is unavailable or another request is busy.
